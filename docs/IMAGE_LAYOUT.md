# 出勤キャスト画像のレイアウト（背景固定・キャスト自動配置）

実装: `assets/js/image-generator.js`（描画・配置計算）、`gas/BackgroundService.gs`（背景の保存・写真の取得）
テスト: `tests/image-generator.test.js`（配置計算）、`tests/background.test.js`（GAS）、`tests/e2e-image.test.js`（Chromium）

## 1. 画像サイズ

| 項目 | 値 |
|---|---|
| 完成画像（キャンバス） | **常に 1447 × 2048 px**（人数・背景の大きさで変えない） |
| 出力形式 | PNG（`canvas.toBlob('image/png')`） |
| ファイル名 | `shift_<店舗>_<YYYY-MM-DD>_1447x2048.png` |

## 2. 背景

- 店舗ごとに 1 枚（PNG / JPEG、8MB まで、短辺 200px 以上・長辺 8000px 以下）。
- **切り抜かない・変形しない**。縦横比を保ったまま、キャンバスに全体が収まる最大の大きさで中央に置く（contain）。
  - 例: 1447 × 2048 → そのまま全面。1080 × 1920 → 1152 × 2048（左右に 147.5px の余白）。2048 × 2048 → 1447 × 1447（上下に 300.5px の余白）。
- 余白の色: 「自動」は背景画像の外周の平均色。手動で `#RRGGBB` を指定することもできる。
- 背景が未登録の場合は白（または指定色）一色で生成する。
- 背景の差し替え・設定変更は「背景設定」シートと Drive の背景フォルダだけを変更し、**シフトデータは変更しない**。

## 3. 配置領域（ヘッダー・フッターを除いた中央部分）

背景のヘッダー（例:「本日の出勤キャスト」）とフッター（店舗名・営業時間など）に写真が重ならないよう、
キャンバスの上下左右から指定した px を除いた範囲にだけ配置する。店舗ごとに保存できる。

| 項目 | 既定値 | 範囲 |
|---|---|---|
| 上（ヘッダー） | 440 px | 0 以上 |
| 下（フッター） | 200 px | 0 以上 |
| 左・右 | 60 px | 0 以上 |
| 配置領域の最小 | 幅 400px・高さ 400px | これより狭い設定は保存できない |

既定値の配置領域は 1327 × 1408 px（x=60, y=440）。

## 4. 写真枠・余白・名前（写真幅 W に比例）

| 項目 | 値 |
|---|---|
| 写真枠 | 縦横比 **3:4**（高さ = W × 4/3）。全員同じ大きさ |
| 写真の当てはめ | 写真枠を埋めるように拡大し、中央（上下は上寄り 25%）で切り抜く ※背景は切り抜かない |
| 写真枠の上限 / 下限 | 520px（1人でも大きくなりすぎない）/ 80px（これより小さくなる場合は配置不可） |
| 横の間隔 | max(W × 0.10, 12px) |
| 写真〜名前 | max(W × 0.04, 6px) |
| 名前の枠の高さ | max(W × 0.22, 34px) |
| 段と段の間隔 | max(W × 0.10, 16px) |
| 名前の枠の幅 | 写真幅 ＋ 左右の間隔の半分ずつ（隣の名前枠と重ならない・配置領域の外に出ない） |
| 写真なし | 「NO PHOTO」のプレースホルダー（店舗の画像フォルダに「準備中」画像があればそれを使用） |

W は「配置領域に収まる最大の整数」（`maxPhotoWidthFor`）。人数が増えても**キャンバスは変えず、写真枠と余白だけを縮める**。

## 5. 人数別レイアウト（段数）

| 人数 | 段数 | 段ごとの人数（例） |
|---|---|---|
| 0 | – | 背景のみ |
| 1 | 1 | 中央に 1 人 |
| 2〜3 | 1 | 中央揃え |
| 4〜5 | 2 | 4 → 2/2、5 → 3/2 |
| 6〜8 | 2 | 6 → 3/3、7 → 4/3、8 → 4/4 |
| 9〜10 | 2 | 9 → 5/4、10 → 5/5 |
| 11〜13 | 3 | 11 → 4/4/3、12 → 4/4/4、13 → 5/4/4 |
| 14〜 | 3 段以上 | 写真が最も大きくなる段数を自動選択（同じなら段数の少ない方） |

- 段ごとの人数は上の段から多めに割り振る（差は最大 1 人）。
- **各段を左右中央揃え**（最終段が少人数でも中央）。段のまとまりは配置領域の上下中央。
- **シフトの並び順を保持**（左上から右へ、上の段から順）。
- **休みのキャストは描画しない**（出勤のみ）。

既定の配置領域での写真幅（参考）: 1人 520 / 3人 414 / 5人 414 / 8人 308 / 10人 245 / 13人 245 / 16人 210 / 20人 210 px

## 6. 名前の文字

- 写真の下の名前枠（半透明の白いラベル）の中に、太字で中央揃え。
- 1 行で入る最大の文字サイズ（枠の高さの 72% から）を探す。1 行だと小さくなりすぎる場合は 2 行に分けて大きく表示する。
- **名前は省略しない**。最小 10px でも入らない場合は `NAME_TOO_LONG` で生成を中止する（文字を重ねて描かない）。

## 7. エラー（重ねて描かない）

| コード | 意味・対処 |
|---|---|
| LAYOUT_OVERFLOW | 写真が 80px 未満になる。配置領域（上下左右の値）を広げる |
| LAYOUT_OVERLAP | 写真・名前が重なる／領域外に出る（通常は発生しない。安全確認） |
| NAME_TOO_LONG | 名前が長すぎて枠に入らない。名前を短くするか、人数・配置領域を見直す |
| INVALID_AREA | 配置領域が不正（幅・高さが 0 以下など） |
| CANVAS_TAINTED | 外部 URL の画像を直接描いたため PNG を保存できない（アプリは data URL のみ使うため通常は発生しない） |

## 8. 画像の受け渡し（CORS・Canvas 汚染対策）

- Drive のサムネイル URL（`drive.google.com/thumbnail`）を Canvas に描くと、CORS ヘッダーが無いため Canvas が汚染され `toBlob` / `toDataURL` が `SecurityError` になる。
- そのため背景・写真はすべて GAS から **base64（data URL）** で受け取り、同一オリジン扱いで描画する。
  - `getBackground` … 背景フォルダ内のファイルだけ返す（設定シートの fileId が他を指していたら `BACKGROUND_UNAVAILABLE`）
  - `getCastPhotos` … 出勤キャストの写真を Drive API のサムネイル（`=s800`）で取得。**画像フォルダ内のファイルだけ**（任意の Drive ファイルを読ませない）
- E2E で「CORS の無い外部画像を描くと `CANVAS_TAINTED`」になることを確認している。

## 9. 生成の流れ（画面）

1. 店舗・日付を選ぶ（背景は店舗ごとに自動で読み込む）
2. 必要なら背景画像を選び、余白の色・配置領域を調整して「背景・設定を保存」
3. 「画像を生成」… **保存済み**のシフトから出勤者と写真を取得して描画（未保存の編集がある場合は保存を促す。他端末で更新されていれば再読み込みを促す）
4. 「PNG で保存」
